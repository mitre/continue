</Info>

The `gemini` provider talks to the Gemini API at
`https://generativelanguage.googleapis.com/v1beta/`. To reach Gemini models
through Google Cloud instead, see [Vertex AI](/customize/model-providers/top-level/vertexai).

## Configuration

<Tabs>
  <Tab title="YAML">
  ```yaml title="config.yaml"
  name: My Config
  version: 0.0.1
  schema: v1

  models:
    - name: Gemini Flash
      provider: gemini
      model: gemini-flash-latest
      apiKey: ${{ secrets.GEMINI_API_KEY }}
      roles:
        - chat
        - edit
        - apply
  ```
  </Tab>
  <Tab title="JSON (Deprecated)">
  ```json title="config.json"
  {
    "models": [
      {
        "title": "Gemini Flash",
        "provider": "gemini",
        "model": "gemini-flash-latest",
        "apiKey": "<YOUR_GEMINI_API_KEY>"
      }
    ]
  }
  ```
  </Tab>
</Tabs>

`apiKey` is required for this provider.

<Tip>
  Rather than putting the key in the file, store it as a `GEMINI_API_KEY`
  environment variable and reference it with `${{ secrets.GEMINI_API_KEY }}`.
  See [Secrets](#secrets) below.
</Tip>

## Supported roles

Not every [model role](/customize/model-roles/00-intro) works with this provider.

| Role | Supported | Notes |
|------|-----------|-------|
| `chat` | Yes | |
| `edit` | Yes | |
| `apply` | Yes | |
| `summarize` | Yes | |
| `subagent` | Yes | |
| `embed` | Yes | Use a `gemini-embedding-*` model |
| `autocomplete` | **No** | The provider does not implement fill-in-the-middle |
| `rerank` | **No** | Not implemented |

<Warning>
  Assigning `autocomplete` or `rerank` to a `gemini` model fails at request time
  with `Method not implemented`, not at config-load time — so the config looks
  valid until the role is actually used. For reranking, configure a separate
  provider that supports it.
</Warning>

## Models

Google updates this lineup often. The
[Gemini models page](https://ai.google.dev/gemini-api/docs/models) is the
authoritative list; the IDs below are a starting point.

### Chat

| Model ID | Notes |
|----------|-------|
| `gemini-flash-latest` | Alias tracking the current Flash model — a safe default |
| `gemini-pro-latest` | Alias tracking the current Pro (reasoning) model |
| `gemini-flash-lite-latest` | Alias tracking the current lowest-cost model |
| `gemini-3.1-pro-preview` | Latest Pro preview |
| `gemini-3-flash-preview` | Flash preview |
| `gemini-3.1-flash-lite` | Cost-optimized 3.1 |

<Warning>
  Google gates some older model IDs away from **new** API keys: `gemini-2.5-*`
  IDs still appear in the API's model list but return "no longer available to
  new users" when invoked with a recently created key. Existing keys keep
  access. The `-latest` aliases avoid this class of surprise entirely.
</Warning>

Preview IDs change and are eventually retired, so prefer an alias or stable ID
for anything long-lived.

### Embeddings

| Model ID | Notes |
|----------|-------|
| `gemini-embedding-2` | Multimodal embeddings |
| `gemini-embedding-001` | Text embeddings |

```yaml title="config.yaml"
models:
  - name: Gemini Embeddings
    provider: gemini
    model: gemini-embedding-001
    apiKey: ${{ secrets.GEMINI_API_KEY }}
    roles:
      - embed
```

## Secrets

Set the key as an environment variable rather than writing it into the file:

```bash
export GEMINI_API_KEY=your-key-here
```

Then reference it:

```yaml title="config.yaml"
apiKey: ${{ secrets.GEMINI_API_KEY }}
```

The CLI also reads `.env` files. It resolves a secret from the first source that
defines it, in this order:

1. `process.env` — the shell environment
2. `~/.continue/.env`
3. `<workspace>/.continue/.env`
4. `<workspace>/.env`

## Custom endpoints, headers, and proxies

The provider honors `apiBase` and `requestOptions` on every path — chat,
streaming, and embeddings:

```yaml title="config.yaml"
models:
  - name: Gemini via Gateway
    provider: gemini
    model: gemini-flash-latest
    apiBase: https://gateway.example.com/v1beta/
    apiKey: ${{ secrets.GATEWAY_API_KEY }}
    requestOptions:
      headers:
        x-api-key: ${{ secrets.GATEWAY_API_KEY }}
      timeout: 30000
      proxy: http://proxy.internal:8080
```

- `apiBase` — point at an API gateway or regional endpoint
- `requestOptions.headers` — custom headers (e.g. gateway auth)
- `requestOptions.timeout` — request timeout in milliseconds
- `requestOptions.proxy`, `verifySsl`, `caBundlePath`, `clientCertificate` —
  proxying and TLS configuration for corporate networks

## Using Gemini with the CLI

`cn` reads the same `config.yaml`. Because its first-run setup asks specifically
for an Anthropic API key, point it at your config explicitly the first time:

```bash
cn --config ~/.continue/config.yaml
```

See [CLI configuration](/cli/configuration) for details.
